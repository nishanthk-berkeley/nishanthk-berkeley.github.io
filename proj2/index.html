Part 1.1: Convolutions from Scratch

I implemented 2D convolution in two different ways. One of them was a naive implementation with four nested loops (one pair of loops over the output pixels, one pair over the kernel). The other was an optimized version with two loops, replacing the inner kernel loop by using vectorized element-wise multiplication and summing over each image patch. Both flip the kernel before sliding it and zero-pad the image so the output stays the same size as the input. Furthermore, I tested both methods against scipy.signal.convolve2d, then compared runtimes on a 9×9 box filter and the finite-difference operators Dx = [1, 0, -1] and Dy = [1, 0, -1]T. 

def convolution_4_loops(image, kernel):
    kernel = np.flip(kernel)
    kernel_height, kernel_width = kernel.shape
    padded = np.pad(image, ((kernel_height // 2, kernel_height // 2),
                            (kernel_width // 2, kernel_width // 2)), mode="constant")
    height, width = image.shape
    result_image = np.zeros((height, width))
    for i in range(height):
        for j in range(width):
            total = 0.0
            for k in range(kernel_height):
                for l in range(kernel_width):
                    total += padded[i + k, j + l] * kernel[k, l]
            result_image[i, j] = total
    return result_image

def convolution_2_loops(image, kernel):
    kernel = np.flip(kernel)
    kernel_height, kernel_width = kernel.shape
    padded = np.pad(image, ((kernel_height // 2, kernel_height // 2),
                            (kernel_width // 2, kernel_width // 2)), mode="constant")
    height, width = image.shape
    result_image = np.zeros((height, width))
    for i in range(height):
        for j in range(width):
            result_image[i, j] = np.sum(padded[i:i + kernel_height, j:j + kernel_width] * kernel)
    return result_image

Correctness check against scipy

I ran both of my loop implementations against scipy.signal.convolve2d (mode="same", boundary="fill", fillvalue=0) on a 60×60 cropped selfie, using the 9×9 box filter and both Dx and Dy. The max absolute pixel difference was effectively zero. This confirmed that both my 4-loop and 2-loop versions match scipy's convolution exactly.

Part 1.2: Finite Difference Operators

When I convolve the cameraman image with Dx, it picks out the vertical edges of the image (the side of his coat, tripod legs, tower in background), on the other hand, Dy picks out horizontal edges (top of his head, horizon). After combining the two into a gradient magnitude image, sqrt(dx² + dy²), the resultant image gives the edge strength at each pixel regardless of orientation.

The binarized edges are then extracted by using a cutoff threshold against that magnitude. grad_mag > t turns a pixel white if its edge strength beats the cutoff and black otherwise, so the threshold acts as a noise filter on the gradient.

Picking a threshold

I binarized the gradient magnitude with three thresholds, 0.1, 0.15, and 0.2, to see how the cutoff trades off real edges against background image noise:

  • t = 0.1 — This keeps every real edge (coat silhouette, head and camera, tripod legs, building and dome/towers), but the grass is full of white speckle from weak, meaningless intensity changes passing the cutoff.
  • t = 0.15 — This threshold noticeably cleans up the grass while still keeping the main silhouette intact. This resulted in the best balance of the three.
  • t = 0.2 — With this threshold, the grass noise is gone, but the softer parts of the real edges (background building outlines) start breaking into disconnected pieces.

Part 1.3: Derivative of Gaussian (DoG)

The unsmoothed edges seen in Part 1.2 pick up a lot of noise because the finite difference reacts to any high-frequency change, real or not. To fix this issue, I blurred the cameraman image with a 13×13 Gaussian (σ = 2, built with cv2.getGaussianKernel) before repeating the Part 1.2 procedure: partial derivatives, gradient magnitude, then a binarized edge map with the same threshold, 0.1.

What differences do you see?

The difference that comes with blurring first is that it removes almost all of the grass speckle that showed up in Part 1.2 even at the lowest threshold, since the Gaussian averages out the high-frequency noise before the derivative can react to it. The tradeoff is that the real edges get thicker and a little softer/less precise since the blur spreads each edge's intensity over more pixels.

Derivative of Gaussian filters

Since convolution is an associative operation, blurring and then differentiating should be identical to differentiating a single combined filter. This is where the derivative of Gaussian comes in. It is built by convolving the Gaussian with Dx and Dy directly. Convolving the image with these two DoG filters instead of blur-then-diff gives the same gradient and edges.

Part 2.1: Image Sharpening (Unsharp Masking)

A Gaussian blur is simply a low-pass filter, so subtracting the blurred image from the original, high = image − G * image, isolates the high frequencies (which include all the edges and fine detail). Sharpening the image boosts those high frequencies and adds them back on top of the original. Both steps combine into a single convolution, the unsharp mask filter: a scaled impulse minus a scaled Gaussian.

\[ h_{\text{unsharp}} = (1+\alpha)\,\delta - \alpha\,G \qquad\Longrightarrow\qquad \text{image} * h_{\text{unsharp}} = \text{image} + \alpha(\text{image} - G * \text{image}) \]

where δ is the identity/impulse kernel (a 1 at the center, 0 elsewhere) and α controls how much of the high-frequency boost gets added back. I applied this per color channel with a Gaussian of σ = 3, ksize = 6σ + 1 = 19.

Taj Mahal

Varying α

Increasing α turns up how much of the high-frequency layer gets added back: at α = 0 it's just the original image, and as α grows the edges get stronger and more defined until it starts overshooting into visible outlining around high-contrast edges at α = 8.

Part 2.2: Hybrid Images

A hybrid image is one that blends the low frequencies of one picture with the high frequencies of another, so it reads as the low-frequency image from far away and the high-frequency image up close. I low-pass filter one image with a Gaussian, and high-pass filter the other as image − G * image. Then I align the two with matching eye/feature points and add the two filtered results together.

Derek + Nutmeg (full process)

First I aligned the images on the eyes, then filtered with σlow = 8 (Derek) and σhigh = 3 (Nutmeg), low enough to pass Derek's overall face shape while cutting out the cat's fine fur detail, and high enough to keep the cat's whiskers/eyes sharp without letting through Derek's low-frequency skin tone.

Part 2.3: Gaussian and Laplacian Stacks

A stack is like a pyramid but without the downsampling, so every level stays the same resolution as the original. The Gaussian stack's level i is just the image blurred with a Gaussian whose σ doubles each level (σ = 2, 4, 8, 16, ...). On the other hand, the Laplacian stack's level i is the difference between consecutive Gaussian levels (the detail lost going from one blur to the next).

Recreating Figure 3.42 (the "oraple")

Using a hard vertical-split mask (apple on the left half, orange on the right), I blended the two Laplacian stacks level-by-level. Each level of the apple's stack is weighted by the (Gaussian-blurred) mask, each level of orange's stack by 1 − mask, and the two weighted stacks are added and summed across levels to get the final blend. The rows are levels 0, 2, 4, and the final sum; columns are apple's weighted Laplacian, orange's weighted Laplacian, and their sum at that level.

What I Learned

The most important takeaway from this project to me was understanding the significance of Gaussian kernels. The fact that most of the transformations I worked on included a convolution and Gaussian kernel showed me how vital they are in image creation. Even learning that various combinations of different convolution operations give us a lot of freedom in blurring, combining, and sharpening images.
